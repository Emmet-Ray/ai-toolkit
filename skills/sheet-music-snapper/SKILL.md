# Sheet Music Snapper

使用浏览器正常浏览曲谱，逐页截图；用附带脚本裁剪、拼接并保存 PNG。以可见谱面为依据，不依赖某个网站或图片下载接口；图片、SVG、Canvas 或网页 PDF 查看器都可通过截图采集。此技能需要能读取页面状态、滚动或翻页、截图并将截图写入本地文件的浏览器工具，以及 Python 和 Pillow。通用流程不代表所有网站都已经实测；无法确认边界、顺序或完整性时说明具体限制。

## 确定输入

- **保存目录**：用户未提供、当前对话也未明确确认时，先询问确认。不要自行选择项目目录、下载目录或上一次测试目录。目录待确认时可以先搜索、检查曲谱；不要开始生成最终文件。
- **曲谱链接**：用户给出具体链接时，使用该曲谱。
- **只有曲名**：按曲名、作者和乐器搜索候选；用户指定网站时限定该站，否则不默认只搜 MuseScore。列出可核实的标题、编曲者/上传者、乐器编制、页数和链接；未查到的字段省略。让用户确认具体版本后再截图，即使只找到一个候选也要确认。不要虚构结果或默认选第一个；站内搜索受阻时可尝试一次搜索引擎，仍无可核实结果则请用户给链接或补充乐器、作者。
- **多个链接**：每份曲谱分别处理，共用已确认的父目录，分别新建曲名文件夹。

## 浏览和截图

使用当前环境支持的 Computer Use/浏览器工具，并先阅读它的操作、截图和保存文件文档。Chrome/CUA 的已验证操作示例见 [references/browser-capture.md](references/browser-capture.md)，开始截图时再读。

1. 从页面核实曲名、谱面边界与浏览方式。文件夹使用实际曲名，例如《女儿情》用 `女儿情`，不要把网页标题中的乐器、难度、网站名一并带入。
2. 按页面实际结构选择采集方式：连续排列的纸页在实际滚动容器内滚动；单页或双页查看器使用可见翻页控件，等页码和内容稳定后再记录。页面可能延迟加载或移除离开视口的页；记录已看到的页号，不以一次 DOM 快照中的元素数量推断总页数。页数未标明时，浏览到可核实的末页/末尾后再确定总数；不能把加载失败或翻页无响应当作结束。
3. 清除遮住谱面的提示、弹窗或菜单，避开固定播放器和侧栏。保持截图期间的谱面缩放、窗口尺寸不变。优先保留当前可读清晰度，避免为塞进一张截图而缩小谱面。
4. 一页超过视口高度时，拍摄有重叠的上下片段，随每张截图记录谱面边界、未被遮挡的区域和视口尺寸。使用同一套浏览器截图与 DOM 坐标，不混用原生窗口截图坐标。不写死这里或以前运行时的坐标、缩放或页高。
5. 只截图正常浏览可见的页面；遇到登录、验证码或付费阻挡时，按工具规则交接并报告缺哪些页。不要通过猜图片 URL、隐藏接口、移除访问阻挡等方式获取不可见页。

短暂白屏不代表空白谱页。确认加载后再截图；发现页号缺失、谱面截断、浮层、比例变化或覆盖不全时，针对问题补拍。页面确实受阻时停止重试，保留已有临时截图并说明缺页，不宣称整份完成。

对没有纸张分页的连续长谱，先核实顶部、底部和稳定宽度，将整份视为一个逻辑页，用重叠截图拼成 `1.png`，交付时说明是长图。页面过长、动态重排或边界不可可靠测量时，先与用户确认按乐谱系统之间的空白处分段；按原顺序编号，说明是采集分段而非原谱页码，不切断谱行。不可把横向隐藏的谱面当作已采集；优先使用查看器的正常横向适配功能并复核清晰度，仍无法完整显示时报告限制，不将二维拼接当作脚本已有能力。

## 生成文件

按截图参考构建 manifest，运行：

```bash
python /path/to/sheet-music-snapper/scripts/stitch_score.py /tmp/score-capture/manifest.json \
  --output-dir "/用户已确认的保存目录"
```

脚本使用 Pillow；缺少依赖时，在当前虚拟环境中运行 `python -m pip install -r /path/to/sheet-music-snapper/scripts/requirements.txt`，或用 `uv run --with Pillow python ...`，不要全局安装。以实际技能目录替换 `/path/to/sheet-music-snapper`。

- 输出固定为 `保存目录/曲名/1.png`、`2.png`……，从 1 开始，不补零；PNG 不再引入 JPEG 有损压缩，但无法恢复截图源已有的压缩损失。
- 有纸张分页时保留原谱分页和页面留白，不把多页合成最终长图，不重新排版乐谱。无分页长谱或已确认分段按上述逻辑页处理。
- 脚本检查连续页号、截图覆盖、尺寸和明显空白/重复页，并拒绝覆盖已有曲名目录。同名目录已存在或两份曲谱同名时，让用户选择新目录或文件夹后缀，再用确认后的名称更新 manifest 的 `title`；不要自动覆盖或混入其他版本。
- 顶部/底部不可见部分只有在确认属于空白页边距时才能用 manifest 的 `blank_edges` 补白；任何音符、文字或其他未知区域都必须补拍。
- 临时截图、manifest 和测试预览放在工作临时目录，不放进曲名文件夹。最终文件夹只包含按页编号的 PNG。

## 检查和交付

打开最终图片或拼成临时预览，核对页数、顺序、谱面首尾、拼接处和边缘。脚本的覆盖检查不能识别浮层、所有未加载情况或音乐内容是否缺失，不能代替视觉检查。

交付时给出每份曲谱的文件夹链接、实际页数和图片尺寸，并嵌入预览。清楚区分完整成功与部分完成；不要把仅仅打开网页或拍到首页当作完成。
